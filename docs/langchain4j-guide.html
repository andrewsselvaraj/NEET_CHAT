First, what is LangChain?

LangChain is a family of libraries and patterns for building software around language models. It helps applications connect a model to prompts, retrieved information, tools, and (when configured) conversation history. The model itself is still the component that generates language; the framework helps the application prepare inputs and coordinate the work.

This project is written in Java, so it uses LangChain4j, a Java library in the same ecosystem. The name in this app is specifically LangChain4j, not the Python LangChain package.

In one sentence: NEET Paper Coach finds useful excerpts from its PDFs, packages the excerpts with the student's question, and asks a chat model to explain them.

One question, end to end

The paper search is local application code. LangChain4j is the adapter used for the final chat-model call.

The whole PDF collection is not sent to the model. The app searches its local index first, then sends the student's question and only the selected text extracts.

Where the concepts live in this code

1. Model connection

LanguageModelConfiguration.java creates a Spring bean of type ChatLanguageModel. That interface gives the rest of the application a consistent way to submit a prompt without building HTTP requests itself.

The implementation is OpenAiChatModel. Its settings include the API key, API base URL, and model name. These settings select the service/model; they do not contain the NEET papers or the app's retrieval logic.

2. Retrieval and PDF indexing

QuestionPaperIndex.java uses Apache PDFBox to extract text at startup. It splits page text into chunks of about 1,200 characters with 180 characters of overlap, keeping the source filename and page number.

For a question, it tokenizes words, removes common stop words, and scores passages with a BM25-style lexical ranking formula. This is custom app code, not a LangChain4j vector database.

3. Prompt and model call

ChatService.java asks the index for five matches, labels each extract with a reference number, then puts the question and extracts into one prompt.

The prompt tells the model to use only those extracts, explain clearly, say when evidence is insufficient, and cite references such as [1]. The assembled context is capped at 8,000 characters.

4. Web response

ChatController.java handles the form request and passes valid questions to ChatService. ChatAnswer carries the answer and PaperCitation entries back to the Thymeleaf page.

The source list is built from the retrieved passages, so the UI can show the paper and page associated with the evidence supplied to the model.

Simplified version of the central operation in ChatService

passages = questionPaperIndex.search(question, 5)
context = formatPassagesWithPaperAndPage(passages)
prompt = instructions + question + context
answer = languageModel.generate(prompt)
return answerAndCitations(answer, passages)

The LangChain4j model bean, simplified

ChatLanguageModel model = OpenAiChatModel.builder()
    .apiKey(apiKey)
    .baseUrl(baseUrl)
    .modelName(modelName)
    .build();

At startup, Spring creates this bean and injects it into ChatService. If no API key is configured, the application fails early with a clear configuration error rather than waiting for the first question.

This pattern is called RAG

RAG means Retrieval-Augmented Generation. “Retrieval” finds relevant source material; “augmented” means that material is added to the model's input; “generation” is the model writing the response.

What this implementation does not do

  • No semantic embeddings or vector database: retrieval is lexical, so it is strongest when the question shares important words with a passage. A concept phrased very differently may be missed.
  • No agent or tool loop: the model is asked once to generate an answer; it is not choosing and invoking tools or planning multiple steps.
  • No conversation memory: each submitted question is handled as a separate prompt. Earlier questions are not automatically added to later ones.
  • No OCR: scanned image-only PDFs have no searchable text until OCR is performed.
Grounding is guidance, not a guarantee. The prompt asks the model not to guess and to cite supplied extracts, but language models can still make mistakes. Check the displayed source pages for important exam preparation decisions.

Configuration and data flow

The model settings come from Spring properties or environment variables: the API key can be supplied as OPENAI_API_KEY or NEET_LLM_API_KEY; the endpoint and model can be set with NEET_LLM_BASE_URL and NEET_LLM_MODEL. The papers directory defaults to Questions.

Keep API keys outside source code and do not commit them. For a hosted model API, the student's question and the retrieved excerpts are sent to that configured service for generation; the full PDF folder is not uploaded by this retrieval flow.
